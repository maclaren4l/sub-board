# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Sub Board: an offline-capable PWA for a youth soccer coach (lineup on a pitch, half clock, sub timer). Plain static files — no build step, no package manager, no dependencies, no tests, no linter. See [README.md](README.md) for the user-facing workflow.

## Running

Serve the folder statically and open it (service worker needs http, not `file:`):

```
python -m http.server 8000   # then http://localhost:8000
```

`window.__subBoard` exposes `{ state, tick }` for poking at game state from the browser console.

## Deploying

Published with GitHub Pages from the root of `main` on `maclaren4l/sub-board` (https://maclaren4l.github.io/sub-board/). Commit, push to `main`, and Pages rebuilds in a minute or two; after a push, check that the live `sw.js` shows the new `VERSION`. All asset paths are relative so the app works under the `/sub-board/` subpath, and `.nojekyll` keeps Pages from processing the files. There is no CI.

## Checking changes

There is no test runner, so changes get checked by driving the served app in headless Chrome (`puppeteer-core` pointed at the installed Chrome, a fresh browser context per run so `localStorage` starts empty). Two toast checks live in [tests/](tests/); `puppeteer-core` is not a dependency of the repo, so install it somewhere else and point `NODE_PATH` at that `node_modules` (and `CHROME` at the Chrome executable if it isn't in the default Windows path). Run `node tests/toast-fixes.js [url] [width] [height]` and `node tests/toast-taps.js [url] [width] [height]`: the URL defaults to `http://localhost:8000/` (or pass the live Pages URL) and the viewport to 393x852, so repeat at 852x393 and 1180x820. They print PASS/FAIL lines and set a non-zero exit code on failure; `toast-fixes.js` takes about 20 s per run, and `toast-taps.js` reports "N/A" where the toast doesn't overlap the bench (phone landscape, iPad). Other ad-hoc check scripts stay outside the repo. Use `touchscreen` taps and `isMobile`/`hasTouch` viewports of 393x852, 852x393 and 1180x820 to cover portrait, phone landscape and iPad. Two things make this practical:

- **Fake the clock.** Inject `Date.now = () => realNow + window.__off` with `evaluateOnNewDocument`, then bump `__off` and wait ~700 ms for the 250 ms tick to credit "10 minutes" without waiting. `window.__subBoard.state` gives the lineup, goalies and per-player stats to assert against.
- **The toast floats above the dock.** `#toast` is `position: fixed`; `placeToast()` sets `--tx` / `--tt` from the `.dockwrap` rect (anchored by `top` + `translateY(-100%)`, not `bottom`, so an iOS Safari toolbar collapse cannot shift it) so it sits 8 px above the dock, centred over it (so it also works in the landscape column), and it is re-placed on every `render()`, on window `resize` (rotation), and once more in a `requestAnimationFrame` after it is shown (so a first frame measured before layout settles doesn't jump). It never covers a dock button. `#toast` itself ignores pointer events and only its Undo button takes taps (`#toast button { pointer-events: auto }`), so in portrait, where it floats over the bottom bench cards, taps still reach them. It stays up 9 s after "N subs made" (with Undo) and 4 s after other toasts; the timer calls `hideToast()`, the single way to hide it. `hideToast()` is also called when a half ends, when ••• opens (the menu opens in the same spot), and on Reset to full team and New game, so no stale toast survives a reset. `toast()` itself does nothing but `hideToast()` while the ••• menu is open (`UI.more`), so a toast firing mid-menu (e.g. "Time is up") never lands on top of it. Keep new dock-adjacent UI clear of that strip.

## Gotchas when changing things

- **Bump `VERSION` in [sw.js](sw.js)** after changing any cached file, or installed phones keep serving the old copy. If you add a file, add it to `FILES` in `sw.js` too.
- **The roster lives on the device, never in the code**: the repo and Pages site are public, so do not put player names in any committed file (the tests use the in-app sample roster). `S.team` (`[{ name, prefs }]`) is the saved team; `fresh(team)` → `withTeam()` builds a new game's players from it, and `newGame` passes `S.team` through. `save()` re-derives `S.team` from `S.players` whenever `S.phase === 'setup'`, so every setup-screen edit (add, paste, remove, position tags) is saved to the team automatically, while Late arrival players (added in `game`) are for that game only. `remove` is permanent for the team, hence its confirm dialog; "Reset to full team" now only marks everyone present. Names do remain in the git history of earlier commits.
- **Saved-state compatibility**: state is persisted to `localStorage` under `sub-board:v1` and merged over `fresh()` in `load()`. New state fields need defaults in `fresh()`; one-off migrations live in `load()` (e.g. the `kitv` flag, and `team` being adopted from the players already on the device when a save predates it). `load()` also resumes a game saved as `running` more than `STALE_MS` (15 min) ago as paused, so closed-app time is never credited as played.
- **`ask()` resolves `true` / `false` from the dialog buttons, or `null` if a newer dialog replaced it.** Where "cancel" means "go ahead" (the kickoff goalie prompts), test `=== false`, not falsiness.
- **Re-renders must not wipe typing.** `render()` / `renderSheet()` go through `keepFields()` (carries named form fields, focus and cursor across `innerHTML` swaps) and `paintInto()` (skips the repaint when a sheet's markup is unchanged). A form whose input should clear after submit has to `reset()` itself, or the kept value comes back.
- **The goalie record follows the lineup.** `syncGoalie()` (called after live-half lineup changes and Undo) keeps `S.goalies[half]` equal to whoever is in spot 0 once the half is live.

## Architecture ([app.js](app.js), one IIFE)

- **Single state object `S`** (persisted) plus a separate non-persisted `UI` object (selection, pending subs, open menus/dialogs). `S.phase` is `setup` → `game` → `summary`; within a game, `S.halfState` is `ready` / `running` / `paused` and `S.half` is 1 or 2. `S.lineup` is an 11-slot array of player ids indexed by formation spot (slot 0 is always the GK); `S.history` is the undo stack of `{ lineup, formation }` snapshots (saves from older builds hold bare lineup arrays, which `undo` still accepts). It is emptied at kickoff and whenever a half ends, so Undo never reaches back across them.
- **Render model**: `commit()` = `save()` + `render()`; `render()` rebuilds `#app` via template-string functions (`setupHTML`, `gameHTML`, `summaryHTML`) and `renderSheet()` rebuilds the settings sheet and dialog. All DOM events are delegated at `document` level: clicks dispatch on `data-act` to the `H` handler table, form submits on `data-form` to `FORMS`. Add a button by emitting `data-act="x"` in a template and adding `H.x`.
- **Clock**: a 250 ms `setInterval(tick)` accumulates elapsed time from `Date.now()` deltas (so backgrounding doesn't lose time), updating `clockMs`, per-player `played`/`bench` stats, and the sub-timer state machine (`idle` → `running` → `due`). `tick` re-renders fully only when `needsRender` is set (and not mid-drag); otherwise `paintLive()` patches just the `data-clock` / `data-subtime` / `data-subarc` / `data-ring` / `data-badge` / `data-wait` nodes. Keep live-changing text addressable via those `data-*` hooks rather than re-rendering.
- **Game screen layout**: `gameHTML()` is composed from `hudHTML()` (half clock + sub-timer ring), `trayHTML()` (queued-sub chips, or Auto-fill / Clear field before kickoff), the bench card grid, and `dockHTML()` (Undo/Clear, main action, ••• menu). The dock's main button is state-driven (Kick off / Make N subs / Pause / Resume / End half once time is up). Ring badges use `S.gameMs` (total game time across both halves, separate from the per-half `clockMs`) as the denominator.
- **Two interaction modes for the same gestures** keyed on `immediate()` (`halfState === 'ready'`): before kickoff, taps/drops place or swap players directly; during a half, bench→field gestures queue `UI.pending` {off,on} pairs that `confirmSubs` applies together. The goalie (spot 0) is guarded by `confirmGoalie` once the half is live, and cleared at halftime so a 2nd-half GK must be chosen (`S.goalies[half]` records who played).
- **Drag and drop** is hand-rolled with pointer events (`pointerdown`/`move`/`up`, ghost element, `dropTarget` hit-testing against `.disc` bounds). `performDrop` translates a drag into the same `H.spot` / `H.bench` handlers used for taps by faking `UI.sel` and a `{dataset}` stub — so drag and tap behavior share one code path. The bench is a 3-column grid with `touch-action: none` on cards, so drags start immediately on touch; with more than 5 on the bench it gets a `.many` class and becomes two rows that scroll sideways (`touch-action: pan-x`, so a vertical drag still lifts a player). Dropping one field player on another goes through `H.spot`'s swap branch, which calls the `swapSpots(a, b)` helper (records undo history, swaps the two spots, clears the selection) and keeps queued subs (they are keyed by player id, not spot).
- **Formations** are tables of `[role, x%, y%]` in `FORMATIONS`; spot index order matters because `S.lineup` is positional. `changeFormation` remaps players by role group. During a game the formation is switched from the chip in the pitch's top-left corner (`formationPick()`, `UI.fm`; it works mid-half, keeps queued subs and the goalie, and toasts with Undo); while its list is open, drags are off and `.pitchwrap.fmopen` lifts the pitch over a page-wide scrim. `autofill` does bipartite matching of players' optional position `prefs` to empty spots.
- **Kit color** drives CSS custom properties (`--kit`, `--kit-ink`, `--gk`) via `applyKit()`, which also picks a keeper color that won't clash with the kit.
- Audio uses WebAudio beeps (unlocked on user gesture; `wakeAudio()` and `beep()` resume a context that a phone lock suspended, since tones scheduled on a frozen clock never sound), `navigator.vibrate` (no-op on iOS), and the Screen Wake Lock API.
- **Layouts**: portrait is a flex column (HUD, pitch, then a `.side` block with tray, bench and dock). `styles.css` has two landscape variants: iPad (`min-width: 900px`) and a compact phone one (`orientation: landscape` and `max-height: 520px`, about 852x393) that puts the pitch left and a 400px column on the right. The phone rule sits after the other size rules on purpose, since it relies on source order to override them.
